**Description.** `DiscButton` draws its tap area as a fixed 46x46 dp box. The UI dump of the shipped x86_64 release build reports these controls at 46x46 dp, while Android accessibility guidance and the Accessibility Scanner flag targets under 48x48 dp. Other app buttons (IconButton, chips, list rows) measure 48 dp or more, so only this shared widget is short. The labels are present (`semanticLabel: tooltip`), so TalkBack is fine; only target size is affected. S1: 2 dp short, buttons are well separated.

**Steps to reproduce.** 1. Open Contacts. 2. `adb shell uiautomator dump`; read the bounds of `content-desc="Menu"` and `"Add contact"`.

**Expected.** At least 48x48 dp.
**Observed.** 138x138 px at density 480 (3.0) = 46x46 dp; same for detail Back/Edit, Review queue "Scan cards", Duplicates "Check the whole library again".

**Evidence.**
- UI dump (Contacts): `View desc=Menu w=46 h=46`, `View desc=Add contact w=46 h=46`
- UI dump (detail): `View desc=Back w=46 h=46`, `View desc=Edit w=46 h=46`
- Screenshots: `audit/artifact/screens/01_launch_empty.png`, `audit/artifact/screens/09_detail_long.png`

**Impact.** User: slightly harder to hit for users with motor impairments; will be flagged by Accessibility Scanner / Play pre-launch report.
**Recommended remediation.** Make the SizedBox 48x48 (or wrap in `ConstrainedBox(minWidth/minHeight: 48)`) keeping the 46 dp visual disc.
**Verification procedure.** Re-dump the four screens; every DiscButton reports >= 48x48 dp.

**References.** WCAG 2.2 SC 2.5.8 Target Size (Minimum); Android accessibility "touch target size 48dp"; MASVS n/a.
