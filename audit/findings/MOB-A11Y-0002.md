**Description.** On the Scan screen the three mode buttons report 80x34, 59x34 and 46x34 dp in the UI dump. Height is well under 48 dp, and "Pile mode" is also under 48 dp wide. The scanner is used one-handed at events, which makes small targets more costly.

**Steps to reproduce.** 1. Contacts > Scan card, allow camera. 2. `adb shell uiautomator dump`; read the bounds of "One card mode", "Batch mode", "Pile mode".

**Expected.** Each target at least 48x48 dp (visual pill can stay smaller, with padding to the tap area).
**Observed.** `Button One card mode w=80 h=34`, `Button Batch mode w=59 h=34`, `Button Pile mode w=46 h=34`.

**Evidence.** UI dump above; screenshot `audit/artifact/screens/13_scan.png`.

**Impact.** User: mis-taps between modes; Accessibility Scanner flag.
**Recommended remediation.** Give the mode buttons `minimumSize: Size(48, 48)` / `tapTargetSize: MaterialTapTargetSize.padded`.
**Verification procedure.** Re-dump the Scan screen; all three report >= 48 dp in both dimensions.

**References.** WCAG 2.2 SC 2.5.8; Android touch target guidance (48 dp).
